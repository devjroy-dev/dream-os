## 1 · WHAT WAS WRONG

`docs/db/PUBLIC_SCHEMA.md` is written by a PAIR of scripts that each destroy the other's leftovers. `format_public_schema.js:452-457` reads the existing file, cuts at the sentinel, and keeps **only the sentinel-onward tail**. `append_constraints_to_public_schema.js:181-184` does the exact mirror — `head = existing.slice(0, cut)`, then writes `head + md`. Every byte of that document belongs to exactly one generator and is regenerated by it. **There is no region where hand-authored prose survives the pipe.**

F-SW.3's standing cure — *every migration filling a reserved hole must name itself in this header*, ruled CE-32 — was written **into the header**. Into the region that dies at `format`. It had been self-deleting since the day it was authored and survived only because no regen ran between CE-32 and now.

**The scope was wider than the charter knew.** `grep` for the warning paragraph's own words across the generator returns zero: the formatter emits the ⏳ staleness sentence at `:400` and goes straight to `**Project:**` at `:401`, with nothing between. The doomed region was doc lines **8–14 entire** — the blank, the ⚠ warning paragraph, the blank, the table header, the separator, and both rows. **Seven lines, and one of them was the instruction that makes migration authors write there at all.** The reader would have lost the register and the sentence announcing a register exists, in the same run.

**The disease had a fresh victim at seating.** P2 ZIP1 (`85a652a`) added the `0088` row into that region under R-34.18(i) — one insertion, none removed, a correct and well-made row committed straight into a grave. It also shifted the sentinel from `:1141` to `:1142`, which made the charter's own line number a casualty of the defect the charter describes.

**And the document was already contradicting itself.** Line 6's *derived* holes list stated that `0088` and `0098` carry no file anywhere in `db/migrations/`; the directory held both. Eight lines below, the register said both were applied. One document, two flatly opposed claims — and the direction was the wrong one: **the false claim was the script-owned one that survives regen, the true claim was the hand-authored one that dies.**

**Nothing watched any of this.** `grep -rln` for either generator across `scripts/` in `dream-os` and `dreamos-pwa`: zero cells, re-derived at `85a652a`. That absence is the root cause. Unit-testing the renderer would never have caught it — the old cure did not render wrong, a *different script deleted it afterwards*.

## 2 · WHAT SHIPPED

**`db/migrations/OUT_OF_ORDER.json` — NEW.** The register's data, hand-authored and legally so: it is not a generated file. Sited with its subject, not its renderer (R-34.41), because the person who must edit it is a migration author already standing in `db/migrations/`, and nobody in that state thinks to look in `db/queries/`. Verified inert to every programmatic reader of that directory — all filter `.sql`. Carries a `_README` stating the standing duty, the field contract, the three aborts, and when a row may be removed.

**Shape (R-34.42): four fields, `number` the only structured one.** `note`, `stale_for` and `state` are verbatim markdown rendered into cells unchanged. Decomposing into `{table, from_cols, to_cols}` would mean re-deriving prose like *"The body below still says 13."* at render time, and the two existing rows could not then be carried byte-faithful.

**One deviation from the proposal, flagged for ratification:** the **filename is not stored** — it is derived off `ladder.numbered` at render time by number. This is what makes the field count exactly four as ruled, it reuses the lookup the abort already performs, and it means a renamed migration corrects its own cell on the next run. It is §2c's model applied one level further. If the chair wants the filename hand-held, say so and it becomes a fifth field.

**`db/queries/format_public_schema.js` — MODIFIED.** `readOutOfOrderRegister()` + `renderOutOfOrderRegister()` added after `pad()` at `:177`; call site inserted between the staleness sentence and `**Project:**`. The prose moves **into generator string literals** — a copy move, byte-unchanged, not a rewrite. **The warning paragraph becomes script-owned in the same act**, which is the half of the cure the charter did not know it needed.

**Path is FIXED and read UNCONDITIONALLY** — deliberately not an argv like the array overlay at `:302`. An optional argument a regen run forgets writes a document with no register and no warning, exits zero, and looks cured. The overlay can afford optional: the header discloses it and it self-retires. The register is permanent and its absence is silent.

**Three aborts, all writing nothing:** (1) the register file is missing or unparseable; (2) a record names a number with no `.sql` in `db/migrations/`; (3) a record's number is not below the ladder tip — which is what out-of-order *means*. (2) and (3) are R-34.43, mandatory as ruled, modelled on the overlay's refusal to apply a row matching nothing. **(1) is not ruled and is flagged for ratification:** without it a missing input reproduces the disease exactly — silent absence, exit zero.

**`scripts/b15_schema_register_bench.js` — NEW.** The pipe-run bench.
